# Launch Checklist

## Must-have before public repo

- [ ] public-safe README
- [ ] early README disclaimer: no product-limit bypass, credential sharing, or unscoped external actions
- [ ] sanitized skill docs
- [ ] agent_progress.py included
- [ ] private data scan clean
- [ ] architecture/failure/context docs
- [ ] public launch framing reviewed
- [ ] demo runbook
- [ ] GitHub repo under personal account
- [ ] initial release post drafts

## Public-safety copy scan

- [ ] no "bypass credits", "evade limits", "unlimited", "exploit", "jailbreak", or "ToS workaround" claims
- [ ] social/video copy uses local app workflow and account-boundary framing
- [ ] watcher prompts prohibit secrets, permission dialogs, purchases, public posts, messages, and pushes without explicit scope
- [ ] demo assets use toy/sanitized repos and blurred account/session names
- [ ] docs make clear that users are responsible for respecting the terms, policies, and plan limits of the apps/accounts they operate

## Nice-to-have

- [ ] architecture image
- [ ] 60-90 sec demo video
- [ ] sample watcher cron
- [ ] sample report
- [ ] pinned X post draft

## Launch sequence

1. Local cleanup and validation.
2. Create public GitHub repo.
3. Push initial commit.
4. Record or assemble demo asset.
5. Publish X thread with repo link.
6. Publish LinkedIn post.
7. Reply to early questions with concrete failure modes and lessons.
